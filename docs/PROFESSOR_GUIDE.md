# Professor Guide

Подробная инструкция для преподавателей, которые сопровождают проекты и выставляют итоговую оценку.

## 1. Где преподаватель работает

Основные страницы:
- `/dev/professor` — дашборд преподавателя;
- `/dev/professor/reviews` — входящие приглашения на ревью;
- `/dev/professor/criteria` — настройка критериев;
- `/dev/professor/grading` — оценивание проекта.

## 2. Что преподаватель видит на дашборде

На `/dev/professor` преподаватель видит:
- общий список проектов своего faculty-контура;
- число проектов в работе;
- число входящих приглашений;
- быстрые действия по тем проектам, где от него ожидается решение.

Важно:
- преподаватель может просматривать весь каталог проектов своей faculty-зоны;
- изменять критерии и оценки он может только там, где у него есть назначение или проектная роль.

## 3. Как принять или отклонить приглашение на ревью

Страница: `/dev/professor/reviews`

1. Откройте список ожидающих проектов.
2. Для каждого проекта выберите:
   - `Принять`
   - `Отклонить`

После принятия:
- проектный статус преподавателя становится `ACCEPTED`;
- команда может использовать это в readiness-проверке;
- преподавателю становятся доступны дальнейшие действия по критериям и оцениванию.

## 4. Как настраивать критерии

Страница: `/dev/professor/criteria`

Преподаватель может:
- выбрать проект;
- просмотреть текущий статус проекта;
- добавлять критерии;
- задавать вес критерия;
- указывать описание;
- следить за суммой весов.

Ограничения:
- у критерия должен быть заголовок;
- вес каждого критерия от `1` до `100`;
- суммарный вес не должен превышать `100`.

Практический совет:
- формулируйте критерии так, чтобы по ним можно было принять бинарное решение `Да/Нет`;
- комментарий лучше использовать для пояснения, а не для дублирования критерия.

## 5. Как сопровождать проект до финала

Во время `ACTIVE` преподаватель:
- не выставляет преждевременную финальную оценку;
- наблюдает за проектом;
- при необходимости проверяет критерии и общую готовность;
- ждет, пока команда завершит задачи и отправит проект на финальное оценивание.

## 6. Как оценивать проект

Страница: `/dev/professor/grading`

Преподаватель видит:
- выбранный проект;
- текущий статус;
- покрытие по критериям;
- число выполненных критериев;
- итоговый балл;
- подсказки по стадии ревью;
- активность команды.

### 6.1 Как работать с листом проверки

1. Выберите проект.
2. По каждому критерию отметьте:
   - `Да`
   - `Нет`
3. Добавьте комментарий, если он нужен.
4. Нажмите `Сохранить оценку`.

### 6.2 Как понять, что оценивание готово к публикации

Оценивание можно завершить, когда:
- проект находится в `GRADING`;
- критерии настроены;
- по каждому критерию есть решение;
- преподаватель назначен именно на этот проект.

### 6.3 Как завершить оценивание

Нажмите `Завершить оценивание`.

После этого:
- итог фиксируется в проекте;
- проект переходит в завершенный статус;
- команда видит итог на вкладке `Ревью`.

## 7. Как вернуть проект на пересдачу

На странице оценивания нажмите `Отправить на пересдачу`.

Что произойдет:
- проект вернется из `GRADING` в `ACTIVE`;
- счетчик пересдач увеличится;
- следующая финальная оценка будет снижена по правилу пересдачи.

Текущий штраф:
- `-5%` за каждую пересдачу;
- максимум `-25%`.

Интерфейс преподавателя сразу показывает:
- количество пересдач;
- текущий накопленный штраф;
- предупреждение, что следующий финал будет опубликован с учетом штрафа.

## 8. Что означает блок `Активность команды`

На странице оценивания преподаватель видит короткую сводку по участникам:
- активность считается по задачам и событиям проекта;
- данные выводятся наглядно, без избыточной детализации;
- это вспомогательный сигнал, а не самостоятельная оценка.

Этот блок полезен, чтобы:
- быстро понять распределение вовлеченности;
- заметить, если один участник работал значительно больше остальных;
- использовать это как контекст при комментариях команде.

## 9. Что важно помнить о пересдаче

Возврат на пересдачу нужен, когда проект:
- формально дошел до финального ревью;
- но требует доработки перед публикацией итоговой оценки.

После пересдачи:
- команда снова работает в `ACTIVE`;
- преподаватель позже возвращается к финальному ревью;
- итог публикуется уже с учетом накопленного штрафа.

## 10. Частые вопросы

### 10.1 Почему я не могу редактировать критерии или оценку?

Обычно причина одна из этих:
- вы не назначены преподавателем этого проекта;
- приглашение на ревью еще не принято;
- проект открыт только для просмотра в faculty-каталоге.

### 10.2 Когда лучше возвращать проект на пересдачу, а не публиковать оценку?

Когда команда еще может исправить существенные проблемы:
- не выполнены ключевые критерии;
- есть заметные пробелы по результату;
- проект рано завершать окончательно.

### 10.3 Обязан ли блок активности совпадать с итоговой оценкой?

Нет. Активность — это вспомогательный сигнал. Основная оценка должна опираться на критерии.

## 11. Полезные советы преподавателю

- Сначала примите приглашение, потом настраивайте критерии.
- Не держите проект в `GRADING`, если он фактически требует доработки: лучше вернуть на пересдачу.
- Перед финальной публикацией проверьте, нет ли накопленного штрафа за пересдачи.
- Используйте блок активности как ориентир, но итог привязывайте к критериям.
- Если по проекту не хватает контекста, сначала откройте сам проект и посмотрите задачи, прежде чем публиковать финальный результат.
