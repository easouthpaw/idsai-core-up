Используется задеплоенное приложение с seeded-данными.

## Блок 1. Регистрация и профиль (1–2 мин)

**Цель:** показать онбординг нового пользователя.

1. Открыть главную страницу. Показать landing page.
2. Нажать `Зарегистрироваться`.
3. Заполнить форму (можно использовать реальный email или demo-аккаунт).
4. После входа — открыть `Настройки профиля`:
   - загрузить аватар;
   - заполнить ФИО, выбрать университет и факультет.
5. **Акцент:** система определяет принадлежность пользователя к тенанту через email-домен; каждый тенант — отдельное учебное заведение.

---

## Блок 2. Создание проекта (2–3 мин)

**Аккаунт:** `aibolat.student@idsai.local`

1. Перейти на `/dev/projects`.
2. Нажать `Создать проект`.
3. Заполнить:
   - название: **"Система анализа успеваемости"**
   - краткое описание
   - README (markdown)
   - ссылка на GitHub
   - видимость: `Приватный` → выбрать группу
4. Нажать `Создать`.
5. **Акцент:** тимлид автоматически получает роль TEAM_LEAD. Проект стартует в статусе `DRAFT`.

---

## Блок 3. Подготовка команды (2 мин)

**Аккаунт:** `aibolat.student@idsai.local` (продолжение)

1. В карточке проекта → вкладка `Команда`.
2. Добавить позиции:
   - Backend Dev (2 слота)
   - Frontend Dev (1 слот)
3. Нажать `Открыть набор` → статус переходит в `RECRUITMENT`.
4. **Акцент:** без позиций нельзя открыть набор и нельзя создавать задачи.

---

## Блок 4. Вступление участников в проект (1–2 мин)

**Аккаунт:** `aliya.student@idsai.local`

1. Перейти на `/dev/projects` → найти проект (он публичен или доступен группе).
2. Подать заявку на позицию `Backend Dev`.

**Аккаунт:** `daniyar.student@idsai.local`

3. Подать заявку на `Frontend Dev`.

**Аккаунт:** `aibolat.student@idsai.local`

4. Вернуться в проект → вкладка `Команда` → принять обе заявки.
5. **Акцент:** тимлид контролирует состав; участник не попадает в команду без подтверждения.

---

## Блок 5. Назначение преподавателя (1 мин)

**Аккаунт:** `aibolat.student@idsai.local`

1. Вкладка `Ревью` → нажать `Пригласить преподавателя`.
2. Выбрать `nurzhan.prof@idsai.local`.
3. Нажать `Отправить приглашение`.

**Аккаунт:** `nurzhan.prof@idsai.local`

4. Перейти на `/dev/professor/reviews`.
5. Найти приглашение → нажать `Принять`.
6. **Акцент:** без принятия приглашения преподавателем проект не может быть переведён в `ACTIVE`.

---

## Блок 6. Настройка критериев и запуск проекта (1 мин)

**Аккаунт:** `nurzhan.prof@idsai.local`

1. Перейти на `/dev/professor/criteria`.
2. Выбрать проект.
3. Добавить 2–3 критерия (например: "Работающий API", "Документация", "Код-ревью пройден"), распределить веса.

**Аккаунт:** `aibolat.student@idsai.local`

4. В карточке проекта нажать `Запустить проект` → статус переходит в `ACTIVE`.
5. **Акцент:** кнопка становится доступна только когда набрана команда, преподаватель принят и критерии заданы — система сама проверяет готовность.

---

## Блок 7. Работа с задачами (2–3 мин)

**Аккаунт:** `aibolat.student@idsai.local`

1. Вкладка `Задачи` → нажать `Создать задачу`.
2. Заполнить: название "Реализовать REST API", позиция `Backend Dev`, назначить на `aliya.student`, срок через неделю.
3. Создать ещё одну задачу: "Верстка дашборда" → позиция `Frontend Dev`.

**Аккаунт:** `aliya.student@idsai.local`

4. Перейти на страницу проекта → вкладка `Задачи`.
5. Нажать `Взять в работу` на своей задаче → статус `IN_PROGRESS`.
6. Когда готово — нажать `Завершить задачу`, добавить комментарий и вложение.

**Аккаунт:** `daniyar.student@idsai.local`

7. Аналогично завершить вторую задачу.

8. **Акцент:** лента активности по задачам фиксирует все изменения — кто и когда взял в работу, изменил статус, завершил с комментарием.

---

## Блок 8. Отправка на оценивание (1 мин)

**Аккаунт:** `aibolat.student@idsai.local`

1. Убедиться, что все задачи в `DONE`.
2. На вкладке `Описание` → нажать `Отправить на оценивание`.
3. Статус проекта переходит в `GRADING`.
4. **Акцент:** кнопка заблокирована пока есть незавершённые задачи — система не даёт отправить "сырой" проект.

---

## Блок 9. Финальное оценивание (1–2 мин)

**Аккаунт:** `nurzhan.prof@idsai.local`

1. Перейти на `/dev/professor/grading`.
2. Выбрать проект.
3. Отметить выполненные критерии.
4. Написать итоговый комментарий.
5. Нажать `Завершить оценивание` → статус `COMPLETED`.
6. **Акцент:** преподаватель видит всю активность команды по задачам прямо на странице оценивания — не нужно верить на слово.

---

## Блок 10. База знаний (опционально, 1 мин)

**Аккаунт:** `admin@idsai.local`

1. Перейти на `/dev/kb`.
2. Показать структуру разделов и статей.
3. Открыть одну статью — markdown с рендером.
4. **Акцент:** база знаний доступна всем пользователям тенанта; контент пишется в markdown прямо в браузере.

---

## Итоговые тезисы для комиссии

- **Мультитенантность:** каждый университет — изолированный тенант. Данные не пересекаются.
- **RBAC:** права настраиваются на уровне системы, факультета и конкретного проекта.
- **Полный жизненный цикл:** от создания проекта до публикации итоговой оценки.
- **Аудит:** лента активности задач фиксирует все действия с временными метками.
- **Отказоустойчивость:** Redis кэширует RBAC, при отказе — прозрачный fallback на БД; MinIO для файлов, при отказе — локальное хранилище.
