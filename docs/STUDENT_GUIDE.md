# Student Guide

Подробная инструкция для студентов и участников проектных команд.

## 1. Где студент работает

Основные страницы:
- `/dev/projects` — список своих проектов и создание нового.
- `/dev/project?project_id=...` — карточка конкретного проекта.

На странице проекта студент обычно работает через вкладки:
- `Описание`
- `Команда`
- `Задачи`
- `Критерии`
- `Ревью`

Состав доступных вкладок зависит от роли и участия в проекте.

## 2. Как создать проект

Страница: `/dev/projects`

1. Нажмите `Создать проект`.
2. Заполните:
   - название;
   - краткое описание;
   - полное описание / README;
   - ссылку на GitHub-репозиторий;
   - стек;
   - тип приватности.
3. Если проект приватный, выберите кафедру и группу.
4. Подтвердите создание.

После создания:
- вы становитесь владельцем проекта;
- автоматически получаете роль `TEAM_LEAD` в рамках проекта;
- проект стартует как `DRAFT`.

## 3. Как подготовить проект к запуску

В карточке проекта студенту-тимлиду нужно пройти несколько шагов.

### 3.1 Заполнить описание и стек

На вкладке `Описание`:
- проверьте название, описание, README и ссылку на репозиторий;
- укажите технологический стек;
- при необходимости обновите обложку и видимость.

### 3.2 Создать позиции в команде

На вкладке `Команда`:
- добавьте проектные роли, например `Backend dev`, `Frontend dev`, `QA`, `ML engineer`;
- укажите capacity, если одна и та же роль нужна нескольким участникам.

Позиции нужны для:
- набора команды;
- распределения задач;
- readiness-проверки перед запуском проекта.

### 3.3 Открыть набор

После базовой настройки откройте набор проекта.

Что это дает:
- другие студенты могут подать заявку;
- тимлид может приглашать участников;
- проект переходит в `RECRUITMENT`.

## 4. Как собрать команду

### 4.1 Принять заявки

На вкладке `Команда` можно:
- просматривать входящие заявки;
- одобрять участников;
- отклонять заявки;
- назначать им проектные позиции.

### 4.2 Пригласить студентов

На вкладке `Поиск участников`:
- найдите студента по имени или email;
- добавьте комментарий;
- отправьте приглашение.

### 4.3 Менять роли участников

Для активных участников можно:
- менять проектную позицию;
- удалять из проекта;
- настраивать project-level права, если у вас есть доступ к управлению ими.

Важно:
- `TEAM_LEAD` не выдается как обычная проектная позиция;
- тимлид проекта — это отдельная системная роль владельца проекта;
- для обычных участников выбираются только проектные позиции.

## 5. Как назначить преподавателя

На вкладке `Описание` в блоке пайплайна:
- найдите преподавателя по имени или email;
- отправьте приглашение на ревью.

После этого:
- проект хранит назначенного преподавателя;
- его статус ревью становится `PENDING`;
- проект нельзя полноценно запустить, пока преподаватель не подтвердит участие.

## 6. Как работать с критериями

Вкладка `Критерии` показывает критерии оценки проекта.

Студент:
- видит список критериев;
- видит итоговое состояние проверки;
- не настраивает критерии самостоятельно.

Критерии добавляет преподаватель.

## 7. Как запустить проект

Кнопка запуска появляется, когда readiness позволяет перевести проект в `ACTIVE`.

Для запуска должны выполняться все условия:
- созданы позиции;
- набрана команда;
- участникам назначены роли;
- преподаватель подтвердил участие;
- создан хотя бы один критерий.

После запуска:
- проект переходит в `ACTIVE`;
- становится доступна полноценная работа с задачами;
- открывается основной рабочий цикл команды.

## 8. Как работать с задачами

Вкладка: `Задачи`

На доске есть три колонки:
- `К выполнению`
- `В работе`
- `Готово`

### 8.1 Кто может создавать задачи

Создавать задачи может участник с правом `task.create`.

На практике это может быть:
- тимлид;
- task manager;
- другой участник, если ему выдали соответствующее project-level право.

### 8.2 Как создать задачу

1. Нажмите `Новая задача`.
2. Укажите:
   - название;
   - статус;
   - приоритет;
   - проектную роль;
   - исполнителя;
   - описание;
   - срок.
3. Сохраните задачу.

### 8.3 Как создавать задачи для тимлида

Теперь в задачах есть специальная роль `Тимлид`.

Это означает:
- в модальном окне создания задачи можно выбрать `Тимлид`;
- такая задача адресуется тимлиду проекта;
- системная роль тимлида при этом не смешивается с обычными позициями команды.

Важно:
- `Тимлид` в задачах — служебная task-позиция;
- ее нельзя назначить обычному участнику как стандартную командную роль.

### 8.4 Как назначать исполнителей

Для обычной задачи:
- выбирается проектная позиция;
- затем выбирается активный участник с этой позицией.

Для задачи на тимлида:
- выбирается роль `Тимлид`;
- в исполнителях будет доступен тимлид проекта.

### 8.5 Как работает статус задачи

- `OPEN` — задача создана, но не взята в работу.
- `IN_PROGRESS` — задача в работе.
- `DONE` — задача завершена.

Обычно:
- менеджер или тимлид создает задачу;
- исполнитель берет ее в работу;
- исполнитель завершает задачу;
- история отображается в ленте задачи.

### 8.6 Что происходит при просрочке

Если срок задачи прошел, а задача не закрыта:
- карточка подсвечивается;
- появляется бейдж `Просрочено`;
- срок выделяется визуально;
- общий прогресс проекта показывает число просроченных задач.

Но:
- задача не закрывается автоматически;
- проект не штрафуется отдельно только из-за просрочки;
- преподавателю проект все равно нельзя отправить, пока задача не будет доведена до `DONE`.

## 9. Как отправить проект на оценивание

Когда проект уже в `ACTIVE`, студент или активный участник с нужным правом может перевести его в `GRADING`.

Перед отправкой проверьте:
- преподаватель назначен и подтвердил участие;
- в проекте есть задачи;
- все задачи завершены;
- команда закончила работу.

После отправки:
- проект уходит в `GRADING`;
- команда больше не должна продолжать обычный рабочий цикл как будто проект еще в `ACTIVE`;
- преподаватель получает возможность выставить оценки по критериям.

## 10. Что студент видит после проверки

На вкладке `Ревью` студент видит:
- состояние проверки;
- результат по критериям;
- общий итог;
- комментарии преподавателя;
- информацию о пересдаче и штрафе, если проект возвращали на доработку.

## 11. Что такое пересдача

Преподаватель может вернуть проект на пересдачу.

Что происходит:
- проект уходит из `GRADING` обратно в `ACTIVE`;
- команда дорабатывает проект;
- при следующей финальной публикации оценки применяется штраф.

Текущая логика штрафа:
- `-5%` за каждую пересдачу;
- максимум `-25%`.

## 12. Частые вопросы

### 12.1 Почему проект не запускается в `ACTIVE`?

Обычно не хватает одного из условий:
- не набрана команда;
- участникам не назначены позиции;
- преподаватель не подтвердил приглашение;
- не созданы критерии.

### 12.2 Почему нельзя отправить проект на оценивание?

Чаще всего причина одна из этих:
- проект еще не в `ACTIVE`;
- преподаватель не подтвержден;
- нет задач;
- не все задачи завершены.

### 12.3 Почему участник не может создать задачу?

Проверьте:
- есть ли у него project-level право `task.create`;
- обновил ли он страницу после смены прав;
- находится ли проект в `ACTIVE`.

### 12.4 Можно ли создавать задачу на тимлида?

Да. Для этого в создании задачи есть специальная роль `Тимлид`.

### 12.5 Что будет, если задача просрочена?

Она будет визуально отмечена как просроченная, но не закроется автоматически. Проект все равно нужно довести до состояния, где все задачи находятся в `DONE`.

## 13. Полезные советы студенту

- Сначала создайте позиции, потом приглашайте участников.
- Не отправляйте проект преподавателю, пока на доске есть незавершенные задачи.
- Используйте сроки задач как ориентир для команды, даже если система не штрафует автоматически.
- Если проект вернули на пересдачу, смотрите вкладку `Ревью`: там сохраняется контекст предыдущей проверки.
- Если участнику недавно выдали новые project-level права, обновите страницу проекта, чтобы интерфейс подтянул актуальные разрешения.
