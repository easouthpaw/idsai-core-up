- [Student Guide](./STUDENT_GUIDE.md)

## 1. Быстрый обзор ролей

| Роль | Основные страницы | Что делает |
|---|---|---|
| Студент | `/dev/projects`, `/dev/project` | Создает проекты, собирает команду, работает с задачами, отправляет проект на оценивание |
| Преподаватель | `/dev/professor`, `/dev/professor/reviews`, `/dev/professor/criteria`, `/dev/professor/grading` | Принимает приглашение на ревью, настраивает критерии, проверяет и завершает оценивание |
| Администратор | `/dev/admin`, `/dev/groups`, `/dev/kb` | Управляет пользователями, проектами, статусами, академической структурой и операционным контуром |

## 2. Общая логика работы платформы

### 2.1 Основной путь проекта

1. Студент создает проект.
2. Проект проходит этап подготовки.
3. Тимлид открывает набор и собирает команду.
4. Назначается преподаватель.
5. Преподаватель принимает приглашение и настраивает критерии.
6. Проект переводится в `ACTIVE`.
7. Команда работает по задачам.
8. После завершения всех задач проект отправляется на оценивание.
9. Преподаватель либо завершает оценивание, либо возвращает проект на пересдачу.

### 2.2 Основные статусы проекта

- `DRAFT` — черновик.
- `REVIEW` — проект на предзапуске или в подготовке.
- `RECRUITMENT` — открыт набор команды.
- `ACTIVE` — команда работает над проектом.
- `GRADING` — проект находится на преподавательской проверке.
- `COMPLETED` / `ARCHIVE` — итог опубликован, проект завершен.

### 2.3 Важное ограничение по задачам

Проект нельзя отправить преподавателю на оценивание, пока:
- нет хотя бы одной задачи;
- хотя бы одна задача не завершена в `DONE`;
- преподаватель не подтвержден.

### 2.4 Важное ограничение по срокам

Срок задачи (`due_at`) сейчас работает как визуальный контроль:
- просроченная задача подсвечивается;
- у нее появляется бейдж `Просрочено`;
- в прогрессе проекта показывается число просроченных задач.

При этом просрочка сама по себе:
- не закрывает задачу автоматически;
- не переводит проект в другой статус;
- не начисляет отдельный штраф;
- не блокирует студента.

Главный блокер все равно один: незавершенные задачи.

## 4. Частые вопросы

### 4.1 Почему проект не запускается в `ACTIVE`?

Обычно не хватает одного из условий:
- не набрана команда;
- участникам не назначены позиции;
- преподаватель не подтвердил приглашение;
- не созданы критерии.

### 4.2 Почему нельзя отправить проект на оценивание?

Чаще всего причина одна из этих:
- проект еще не в `ACTIVE`;
- преподаватель не подтвержден;
- нет задач;
- не все задачи завершены.

### 4.3 Почему участник не может создать задачу?

Проверьте:
- есть ли у него project-level право `task.create`;
- обновил ли он страницу после смены прав;
- находится ли проект в `ACTIVE`.

### 4.4 Можно ли создавать задачу на тимлида?

Да. Для этого в создании задачи есть специальная роль `Тимлид`.

### 4.5 Что будет, если задача просрочена?

Она будет визуально отмечена как просроченная, но не закроется автоматически. Проект все равно нужно довести до состояния, где все задачи находятся в `DONE`.

### 4.6 Что происходит после пересдачи?

Проект возвращается в `ACTIVE`, команда дорабатывает его, а итоговая оценка при следующем финале публикуется с учетом накопленного штрафа.
